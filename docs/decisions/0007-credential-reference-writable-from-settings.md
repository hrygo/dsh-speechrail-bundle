# ADR-0007：凭据引用可以从设置页修改

- 状态：已采纳（2026-10-26）
- 取代：ADR-0004 中「凭据引用与端点一同冻结」的那半条

## 背景

ADR-0004 把 `baseUrl` 与 `credentialRef` 一起冻结为条目配置，只在设置页放出三个 `volatile` 字段（`model`、`language`、`requestTimeoutMs`）。理由是「改动这两个中的任何一个，都会改变本机密钥被送往哪里」。

实际使用暴露了这条理由的边界：它只对 `baseUrl` 成立。实测反馈是「凭据 UI 上不支持重新配置」——设置页把引用渲染成只读文本，未解析时会写「未配置 SPEECHRAIL_API_KEY」，而页面上没有任何可改的入口。用户唯一出路是手工编辑 profile 的 `cordis.patch.yml`。2.0.0 改名导致所有人重填配置之后，这条死路变得更常被撞到。

真正的失败模式不是「用户改错了引用」，而是**界面报告了一个问题却不给任何修复手段**。

## 决定

`credentialRef` 改为 `volatile`，设置页提供可编辑输入框，随保存一起写入。

同时守住两条边界：

1. **`baseUrl` 仍然冻结。** 改变端点才会真正改变「解析出来的密钥送去哪里」，那是条目级决定，不该由插件渲染的页面来改。
2. **只接受名字，绝不接受密钥。** `credentialRef` 的取值必须匹配凭据服务的 `CredentialRef` 语法 `/^[A-Za-z_][A-Za-z0-9_]*$/`，长度上限 128；空串是受支持的状态（该端点不需要鉴权，请求不带 `Authorization` 头，见 ADR-0003）。校验在 Host 的 `parseConfigureRequest` 与设置页各做一次：Host 拒绝非法名字而不是存下它，页面用同一规则先说清楚，避免「保存后报一个看不懂的错」。协议里没有任何字段承载密钥值，设置页既不读取也不写入密钥本体——密钥始终在 Harness 的凭据存储／环境变量里。

## 代价（承认，不掩盖）

- 能打开这个页面的人，从此可以决定「用哪一份本机密钥去打这个端点」。攻击面增量有限但非零：端点不可移动，因此泄露方向固定；可泄露的对象是被引用的那份密钥。缓解手段是上面两条边界，加上「值只能是本机已存在的名字，且改完是否能解析会立刻由三态结论显示出来」。
- 页面多一个字段，测试面因此扩大：写入路径、语法拒绝、清空、冲突，各有对应用例。

## 被否决的方案

- **保持只读，只在页面写清「如何改 YAML」。** 成本最低，但把一个两步的手工操作留在最需要一键修复的位置；用户已经明确报告这是 bug，不是文档缺失。
- **页面直接接受密钥并代为写入凭据存储。** 越界：密钥生命周期属于 Harness，不属于插件；而且会把「谁能读密钥」的边界撕开。
- **开放 `baseUrl` 一起可写。** 那才是真正的重定向：同一个本机密钥可以被送去任意地址。端点保持冻结。
